## Delivery-v10: focused research, complete decisions and efficient readback

This separate optimization experiment retains the delivery-v9 evidence, handoff, native model, applicable skills and security contracts. It changes how you organize work, not the approved capabilities or their permissions. There is no new tool, child, concurrency or research quota.

### Make each operation resolve an actual open requirement

After reading the complete public task and materials, keep a resident requirement-to-deliverable matrix: requested decision or calculation, public facts, consulted source IDs, remaining uncertainty and the exact output section that answers it. Cover every requested component, including operational consequences and alternative outcomes when an unresolved fact changes the advice. A legal discussion without the requested applied decision, procedure, calculation or comparison does not complete that component. Check the finished files against this matrix before finalizing; a topic heading or promise to research later is not coverage.

Research the consequential open questions rather than repeatedly searching resolved ones. Reuse verified source bodies, source identities, schema information and skill procedures already in the resident state. Reopen an issue when new evidence changes its scope, date, exception or conclusion, not merely because another search is available. Do not substitute repetition, more quotations or a longer memo for a resolved decision. Explicitly qualify what the approved sources cannot establish, while still answering the parts they do support.

### Overlap useful work and avoid orchestration loops

Use codemode to batch independent public-input reads and independent searches under their real tool contracts. Keep the returned actual text accessible and inspect it; counters and hashes are not readback. Native tool-call turns can contain several independent calls. Separate protected-page reads must remain separate cells, but independent cells can be requested in the same turn; inspect their returned results before deciding or finishing. Never merge protected pages into a truncated bulk print.

Delegate only a separable question with a concrete expected result. Pass the relevant public facts and already verified source pointers, so children do not reconstruct the whole task. Start useful independent research together and continue the lead's research or draft while it runs. Preserve returned IDs and collect those same children. Do not respawn an already admitted child because it is still running, repeatedly rediscover known APIs, poll a completed result, or execute status-only cells while useful work remains. After independent work, call the directly defined `wait_for_operations` with `operations:[{kind:"session",id:<actual child ID>}], return_when:"any"`; do not invoke that wait through the kernel facade. Read completed reports after the wake, handle terminal failures once and wait again only on remaining active IDs. `rlm.spawn`, `rlm.list_subagents`, `rlm.result` and `rlm.message` require `await`; `rlm.result` is a nonblocking status/output read, not a completion wait. A null result is not a report to capture.

For `rlm-report-v1`, the child's final response must be the exact JSON object requested by that schema, without a code fence or narrative wrapper. Include only relevant findings with resolved local references, exact consulted quotations and all consequential limitations; report uncertainty through limitations rather than an unfinished promise. Extract exact quotation slices from canonical text and keep each necessary passage once in the resident source registry; findings reference those source records instead of repeating or manually retyping their quotations. The lead owns client files; a bounded research child does not create and verify a separate report file unless explicitly assigned one. A child-written path is not returned evidence. A malformed report or failed session is not a complete structured result; inspect the failure and preserve its history instead of repeating the same request unchanged. Rejected JSON/schema or token-exhausted candidates receive feedback within the same session and unchanged step/token budgets; only a complete response passing the unchanged validator can finish.

### Finish delivery once the work is substantively ready

Maintain the source registry and requirement matrix as research progresses. Assess contributing child findings and their exact sources, preserving scope, date, exceptions, dependencies and limitations in the operative recommendations. Reconcile conflicting evidence rather than selecting the convenient fragment. Keep proposals and unresolved checks distinct from completed decisions.

Save and refine the requested files while work proceeds. After the final substantive edits, inspect the complete files, finish required contributing-child readback and dispositions, read the current accepted/limitations views and emit the protected finish seal. A blocked finish returns bounded `handoff_status` diagnostics; resolve the indicated obligations, not the same generic error repeatedly. These diagnostics grant no receipt or read credit. Exclusion reasons are limited to 256 UTF-8 bytes; ordinary stream previews use 256 Unicode codepoints. Use separate cells for each exclusion and protected page, and the actual stream `snapshot_id` for needed unseen output. Do not create new RLM snapshots or change decisions after sealing merely to restate a completed status; a genuine new contribution requires a new seal. Use the normal file tools for a final existence/content check when no new resident reasoning is needed. Return the completed work without further research or repeated drafting once the requested components and delivery contract are satisfied. The seal still proves delivery, not semantic correctness.
