# Native capability-v7 comparison

This is a separate experiment, not a replacement for the historical
`opulent-context-v6` comparison. Keep the frozen task packets, rubric, corpus,
historical answers and scores unchanged, and use new checkpoint and grading
directories. Resume requires identical effective provenance.

Both answerers use native RunAnywhere `mimo-v2.6-pro`, with no Gateway fallback
or undocumented reasoning-effort control. Declare the matched parent turn
budget explicitly; the fresh launch uses 1,000 steps, 32,768 completion tokens
per request, a one-hour sandbox lifecycle and a ten-minute inference request
deadline. These are resource safeguards, not an unlimited-run claim. Opulent
descendant calls are additional compute and must be accounted for separately
before being rolled into its total once.

Harvey remains the pinned public LAB harness with its six upstream filesystem
tools and network policy. The opt-in `public-task-v2` prompt permits the supplied
public task file while retaining the prohibition on rubrics and reference
answers. It removes the duplicate task prose; legacy and QA prompts remain
unchanged. Harvey does not acquire Opulent's APIs.

Opulent's versioned generic instructions direct persistent RLM work, useful
VM-backed delegation, Python codemode and applicable procedure invocation on the
assigned legal materials. Its full configured surface is visible and permitted;
there are no added RLM-call, child-depth or session-concurrency quotas. Provider
availability, repository scope, authentication, secrets and human workflow
approvals still apply. Bounded children return findings and evidence rather
than duplicating the coordinator's complete delivery obligation.

Scripted execution forwards its declared deadline to both the E2B stream and
broker client. Ordinary process streams use the remaining configured sandbox
lifecycle. Owned operation waits are driven while root and child work runs;
sleeping with a pending wait is not completion. Before final accounting,
quiesce workers, retain cancelled/incomplete status and unknown physical-attempt
usage, and preserve actual VM identities independently of live handles.
Termination receipts are not absence proof: check the owned IDs against the
provider after cleanup.

Pin `evidenceReplayVersion: "parent-visible-outputs-v2"`. Replay credits only
actual successful parent-visible IPython stdout/results, completed child
responses and explicitly read overflow pages whose source bodies match the
canonical corpus. Original argument/output hashes remain binding. Failed cells,
unprinted values, hidden broker ledgers and child-only trajectories cannot
supply source credit. Without this version, historical replay is unchanged.

First verify this protocol on a separate unscored legal task. The actual scored
trajectories must then establish useful RLM host calls, persistent state,
completed VM-backed children, codemode broker calls, procedure invocations and
parent readbacks; catalogue registration and an unrelated demo are insufficient.
Keep recoverable tool diagnostics separate from fatal execution failures and
from semantic quality penalties.

Grade saved outputs with Jev and an independent evidence-grounded review. Report
paired task scores on a 0–1 scale, full five-task means, and independently trimmed
means that remove one high and one low task for each system and metric. Retain
judge disagreement, missing coverage, failures and unresolved criteria. Report
provider usage, settled charges and unmetered infrastructure separately; do not
infer a winner or a complete bill from partial evidence.
