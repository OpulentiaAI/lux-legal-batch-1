# Prepared built-in skills

`runtime/skills/<name>/SKILL.md` contains the six adapted built-in skills supplied by the user. `manifest-v1.json` records the complete source attachment hash, each original line range and hash, the adapted artifact hash, and its disposition. The operational contract at the top of each file takes precedence over its complete source-derived procedure where a historical hosted feature is not available. The latter is method reference, never proof of a connected integration or a permission bypass.

The prepared E2B image owner must copy **all six** directories to `/opt/opulent/skills/<name>/SKILL.md`, preserve readable permissions, and verify SHA-256 bytes against `manifest-v1.json`. This repository change does not provision that image. `skill` loads those fixed paths from the sandbox, not the control-plane filesystem; it gives the six allowlisted names priority over workspace and installed plugin collisions. Explicit `skill({command:'list',path:'.agents/skills'})` still lists repository skills, and non-built-in plugin/repository invocation still works. Missing built-in files fail rather than falling back to another name or silently claiming installation.

`renderInstructions({profile:'opulent-prepared-v2', appendix, variant})` opts into the prepared profile. The omitted profile remains the unchanged `standalone-v1` historical baseline. The prepared profile appends `instructions/prepared-v2.md` to that audited base and keeps evaluation appendices last, so noninteractive evaluator output and approval restrictions take precedence. `instructions/manifest-prepared-v2.json` separately records the user-supplied full prompt's source hash and line dispositions. No credential value, historical source identity, personal work log, or hosted session data is part of either profile. External MCP tools require actual approved connections, and tool definitions and dispatch permissions remain governed by `config.allowedTools`.
