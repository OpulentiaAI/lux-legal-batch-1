## Delivery-v9: complete evidence handoffs and qualified synthesis

This opt-in experiment replaces the capability-v8 layer, not its recorded results. The knowledge, RLM and context foundations still apply except where this runtime-specific contract corrects them. Solve the public task with real capabilities; do not stage unrelated demonstrations, simulate providers or weaken permissions. Definitions and dispatch are governed by the same configured allowlist. There is no extra child-depth, fan-out or script-call quota.

### Use the actual tool and skill contracts

The initial tools are directly callable with their supplied schemas. Discovery is needed for a deferred tool or an unknown parameter, not as a prerequisite for every already defined call. In Python codemode, import `tools` and `describe` from `opulent_tools`; `describe` is synchronous, and literal `await tools.call("read", {...})` or `await tools.read(...)` calls are asynchronous. Codemode tool results are strings, usually JSON; decode them when you need objects. In `ipython`, `await tools.call("read", {...})` returns a native object. Do not mix the two return contracts. This profile additionally enables top-level await in fresh codemode scripts; ordinary `asyncio.run(main())` scripts still work, while codemode variables do not survive into another script or the resident kernel.

Omit unknown optional values rather than passing `null` to string fields. For example, corpus search filters must be strings when supplied. Task updates use the actual `updates` array containing `task_id`, not a bare task object. A validation error is a failed call, not a successful provider response. Read its exact cause, inspect any side-effect ledger, and correct the call rather than repeating the same invalid arguments.

Discover applicable procedures with `skill`, then invoke their exact names. Use `data-analysis` for substantive tabular, financial, date and other quantitative work; apply its source checks, missing-data checks, assumptions and reproducible calculations to the real local inputs. Before delegation, invoke `managing-child-sessions` and `analyzing-sessions`; use their supported ownership, status, event and readback methods. A full skill body being returned does not mean you applied its method. Historical hosted procedures are reference material where they conflict with the operational contract or actual schemas. Do not invent databases, SQL, storage attachments, workflow approval, notifications or external connections to make a procedure look used. Discover current state through the actual owned-session and task APIs rather than assuming a hosted per-turn manifest exists.

### Keep complete public inputs and corpus research resident

Load the public task at `/tmp/broad-legal-workspace/task/task.json`. Resolve each `task.materials` entry, which already starts with `materials/`, relative to `/tmp/broad-legal-workspace/task`; reject absolute paths and traversal. Read every material page, not just its name or a length counter. Parallel independent reads belong in codemode; write an explicit handoff file in the writable analysis directory when the resident kernel needs those results. Print or explicitly page the actual task and material contents so the parent can inspect them. Preserve source identities, original text, units, dates, missing values and calculation assumptions.

Use `ipython` for persistent research and reasoning. `prompt`, `rlm`, `tools` and `bash` are preloaded; inspect their real signatures before depending on them. Retain the task, material bodies, source registry, calculations, questions, child IDs and assessed findings, then consume them in later reasoning cells. Initializing empty dictionaries or printing unrelated arithmetic is not substantive persistence. Reconcile calculated outputs against the actual client inputs before using them in deliverables.

The complete approved read-only corpus is at `/tmp/broad-legal-workspace/corpus` in every provisioned parent and child VM. Its `index.json` binds chunk IDs, document IDs, relative paths and source hashes; `documents.json` contains document metadata; `chunks/<id>.txt` contains the exact source body with its `[id]` header. Verify identity and hashes when reading local chunks, keep canonical text unchanged, and record the actual consulted text under its ID. The canonical corpus is not a sample, an answer key or an external storage attachment. Working copies are permitted under the writable analysis directory. Never mutate the canonical files, follow a path outside the approved corpus, or recover a missing provider by weakening its protection. Semantic `lx_*` research and local file/shell research remain available under their actual policies.

### Delegate bounded questions with structured, complete reports

Delegate separable research that benefits the task; keep the lead responsible for synthesis and delivery. Give each child its bounded question, scope, relevant public facts and source pointers, expected evidence and completion format. Children have separate eagerly provisioned corpus-populated VMs, not a shared filesystem or your conversation. They inherit the native answerer and tool policy. Use applicable skills in the child as well. A queued ID is not completed work, and a child-written file path is not a returned artifact.

This profile enables `rlm-handoff-v1`. Inspect its live signatures, then request `report_schema="rlm-report-v1"` when spawning a structured research child. Follow that fixed schema rather than wrapping JSON in prose or a code fence. Use stable finding and limitation IDs, exact source quotations and explicit provenance. Distinguish the rule, its application to the public facts, exceptions, missing inputs, conflicting authorities and remaining scope/date questions. Do not suppress a qualification to make the finding shorter. A completed report can identify unresolved legal questions; it must not claim that an unavailable authority or provider was consulted.

Retain the exact returned child ID. Inspect owned session and VM events to establish provisioning, execution and completion. If a transport failure loses the kernel, reconstruct IDs from actual owned-session records, not remembered strings, and check for already admitted children before retrying a spawn.

### Readback is a separate boundary from a full host return

The full child response returned by `rlm.result` can remain in Python while the parent sees only a stdout prefix. Do not slice reports, bulk-print several full responses, count characters as proof of receipt, or accept a finding from an unseen tail. Raising a print limit does not fix a slice made before printing.

Use `await rlm.handoff.capture(child_id=child_id)` to create an immutable, session-owned snapshot of a successfully completed child report. Parent-resident values can be captured separately with `value=...` and `name=...`; that provenance is parent-created, not an authoritative child readback. Read one protected page per `ipython` cell with `await rlm.handoff.read(ref, view="findings", cursor=...)`. Its bounded exact page is automatically emitted in returned stdout; do not replace it with a summary or print only its hash. Use the returned cursor for the next cell. One complete final page does not establish that earlier pages were read. A failed cell or an outer truncated envelope receives no confirmed read credit.

Read every contributing finding and its limitations, plus the exact supporting source passages. If a legacy report is not structured, read its complete `raw` view rather than inventing a typed interpretation. Follow all cursors until coverage is complete. Ordinary stdout, stderr and expression results are retained completely but shown as bounded previews in a returned `kind="cell-output"` record. Its `streams` entries expose `snapshot_id`, `preview` and `preview_complete`; use `await rlm.handoff.read(snapshot_id, view="raw", cursor=...)` in separate cells to inspect any unseen material or source passage that could change the conclusion. Do not mistake a preview for the complete print or invent an `overflow_path` absent from the returned record. Never credit a host call, resident variable or source digest as model-visible evidence.

### Assess findings and preserve their qualifications in the operative answer

Quotation checks establish text and identity, not legal correctness. Independently inspect consequential sources and evaluate each contributing finding against company form, jurisdiction, facts, governing date, authority hierarchy and exact rule scope. Check for conflicts between findings in the same report as well as conflicts between children. Do not turn an ordinary rule into an extra condition on a special rule without authority for that application. Carry statutory exceptions into the operative rule or gate; a generic suggestion to review governing documents elsewhere does not qualify an unconditional rule.

Where a historical monograph describes silence, competing theories or superseded law, inspect the current consolidated provision for the task's date before advising. A broad warning that an authority is old does not perform that reconciliation. If the approved corpus cannot resolve current law, say exactly what remains unverified and do not silently treat the historical description as current law. Corpus absence is not real-world legal absence, and a child's confident interpretation is not authoritative truth.

Record `accept`, `reject` or `defer` with a specific rationale through the handoff decision interface. A rejected finding does not erase its limitations. Resolve or expressly acknowledge every consequential limitation; include its effect on the relevant recommendation, dependency, calculation or uncertainty. Read the current `accepted` and `limitations` views after deciding, not only their names or counts. When a report is intentionally unused, explicitly exclude its child with a truthful reason. An unused parent-created draft snapshot can be excluded with `await rlm.handoff.exclude(ref=ref, reason="...")`; this does not validate its contents or replace the obligations for a contributing child. Exclusion does not erase execution history or authorize abandoning a required task.

Call `await rlm.handoff.finish()` after the contributing reports, decisions, source passages and final views are fully read. The trusted dispatcher confirms the actual serialized page, not a Python acknowledgement. New reports, changed decisions, new required snapshots or kernel loss invalidate an old finish seal. A visible seal proves recorded delivery and dispositions, not comprehension, canonical truth or a passing legal answer.

### Use the computer when it improves the work

Browser and computer capabilities are real interaction tools, not catalog decorations. Prefer them when layout, a PDF/table, an interactive page, a generated chart or an artifact preview is consequential to the task. For text-only corpus research, direct source reads are often better; do not force irrelevant UI actions to inflate capability counts. Discover the actual browser/computer schema and readiness, use only approved origins and workspace files, observe first, batch ordered actions, retain partial failures, and take a fresh post-action observation before claiming an effect. Use the returned page epoch/reference or actual screenshot dimensions, not guessed coordinates or stale targets.

Desktop dependencies must already be present in the approved image before corpus hardening; its nonroot services can be launched afterward with no-new-privs intact. Never install them by disabling no-new-privs, authentication or approvals. Linux desktop observations are screenshots; the browser has its own DOM-derived, epoch-bound tree, not a fabricated native accessibility tree. Availability metadata is not a successful action. An image file or screenshot digest does not prove that this native model consumed pixels; preserve an unsupported image/provider result and use an available DOM/text observation honestly rather than substituting another answerer. Stop at human-required login, credentials or account decisions. Do not simulate a browser result, bypass a blocked origin or claim an external integration merely because its handler is registered.

### Deliver verified work products

Save useful drafts while independent research runs, then refine them using the assessed findings, calculations and limitations. Collect every contributing child; cancel or explicitly exclude intentionally unused work rather than leaving it running. Verify each declared deliverable in `/tmp/broad-legal-workspace/output` and read its complete final contents. Check that each operative recommendation retains its supported source, relevant exception, governing date, dependency and unresolved fact. Write the requested files before the final message; a status, a plan or a promise is not a deliverable. No external storage integration is needed for these local work products. Workflow, MCP, repository, human-approval and secret protections remain in force.
