# Harvey LAB versus the broad legal runtime

This is a separate experiment, not a replacement for the historical three-tool baseline. The Harvey arm uses the actual `OpulentiaAI/harvey-labs` agent loop, OpenAI adapter, prompts and six-tool executor, pinned to commit `845a08840869b21a5c11958aae58bf5f00a7b775`, with an E2B execution backend instead of its native Podman backend. Both answerers and the shared judge use `openai/gpt-6-luna` through AI Gateway. There is no fallback model or code.storage prerequisite. The historical closed-corpus run remains intact and is not directly comparable to this broader protocol.

## What is controlled

Both arms receive all 8,809 canonical text chunks from the same nine-document corpus, exported without the evaluation questions, gold answers, grading rubrics, repository files or credentials. Every exported chunk carries its stable citation ID. The corpus hash covers text hashes and document metadata. The question is passed separately for each run.

Both top-level answerers have a 40-turn ceiling, a 4,000-token per-request output budget and a French, 120-word answer instruction. The word limit is an instruction, not a claim of enforced compliance. The full runtime also exposes delegation, so these limits do not imply equal total model budgets: report descendant usage and tool calls alongside top-level usage. Harvey retains its native filesystem tools and system prompt; the broad runtime retains its own tools and Voyage retrieval. Consequently this compares configured systems, including retrieval and prompts, rather than isolating one agent-loop implementation change.

Both arms must use real E2B execution with source-document write protections and sandbox network restrictions. The broad arm exposes its in-scope runtime tools using Opulent names and calls the four corpus tools through the operator-approved native Arsumbris MCP server, not through its direct corpus dispatchers. Tool visibility does not imply that every optional external provider is configured or working; missing credentials and provider failures remain visible.

## Evidence and grading

The experiment uses the unchanged `eval/gold.json` and the explicitly selected `evidence-v3` judge, with high reasoning effort and 4,000 output tokens. This is **unadjudicated** scoring: known ambiguities in the frozen rubric remain, and a higher number is not proof they have been resolved.

Filesystem and native MCP evidence are conservative: a complete canonical chunk and its ID must actually appear in model-visible tool output before it is supplied as a full source to the judge. A citation, filename, grep excerpt or unreturned corpus lookup does not authorize silently loading the rest of the chunk. Partial excerpts remain in local audit artifacts, but are not upgraded to full sources. This evidence policy can under-credit answers built solely from partial excerpts; inspect those cases before attributing the score gap to legal reasoning. The bounded native MCP decoder unwraps escaped/nested JSON and admits a full source only when its chunk ID, document ID and text exactly match the canonical export. Regression tests reject partial or mismatched sources; a real upstream `lx_chunk` audited through the broad runtime yielded exactly one matching full source. Availability preflight alone still does not establish legal accuracy.

Raw, redacted tool evidence stays in the local artifact directory, outside git; summaries record source hashes and compact audit data. Do not publish licensed source text or authentication material. Failed and degraded cases remain in the planned denominator. Report criterion rate, correct-answer rate, strict all-pass, citation validity, grounding and operational failures separately.

## Running the gated comparison

The authoritative custom corpus build is merge `6b2b6ae1363409ca70693bd79d8fbe89530d1014` (PR #1), not a separate hosted MCP service. Current chunk texts are unchanged from that build; retain the later Voyage client improvements. Its four `lx_*` plugins must be discovered and served by the actual Arsumbris engine/kernel over a corpus-only workspace, rather than bypassed through the standalone three-tool adapter.

The native preflight is now integrated and has passed live without model or judge inference: it provisioned an approved stdio server, listed exactly four LX tools, invoked and verified all four through the scored runtime, denied direct `lx_search`, and exercised the broker callback, prepared desktop, non-root/no-new-privileges sandbox and outbound block. The separate E2B broker round trip also passed. That establishes integration availability, not legal accuracy; scored answers and grading must be reported separately. A fixture test or a registered handler is not a substitute for this live proof.

Install the pinned Harvey checkout and its frozen Python dependencies, and provision the corpus-only Arsumbris workspace documented in [ARSUMBRIS-RUNTIME.md](ARSUMBRIS-RUNTIME.md). The host Python process uses AI Gateway credentials; do not inject them into either model-controlled sandbox. Set `AI_GATEWAY_API_KEY`, `E2B_API_KEY`, `TURBOPUFFER_API_KEY`, and `TURBOPUFFER_REGION` in the host environment, without writing their values into the command, logs, native manifest or artifacts. The E2B bridge additionally requires Python `e2b==2.34.0`, which is not part of Harvey's upstream lockfile. After `uv sync --frozen` in the pinned checkout, install it with `uv pip install --python /absolute/path/to/harvey-labs/.venv/bin/python e2b==2.34.0`. Both its installed version and the upstream revision/clean checkout are checked before execution. The Harvey and broad templates belong to the configured E2B account; loss of access must fail, never silently substitute a base image. The broad desktop template ID is `c2xsaop5g2ny362s3b8v`, with the required root-owned image-manifest SHA-256 `f60ce1097ee693a9bfd6281649cabbcf216572f935cfe1f9109c36a56e6dd29b`. The ID is an alias-backed selection, not by itself a content guarantee; see [`runtime/computer/PROVENANCE.md`](../runtime/computer/PROVENANCE.md).

The broker must bind local port `8788` **and** have its own approved public HTTPS ingress routed to that port; the origin from the successful machine-specific proof is not a portable URL or a default. Set `BROKER_ORIGIN` to the newly approved reachable origin, with no credentials or query parameters in it. The runner checks the local bind, authenticates its E2B callback, and restricts sandbox egress to the exact broker hostname plus an outbound deny rule. With a fresh, empty artifacts directory outside the repository and a separate output path, the two-question command is:

```sh
export BROKER_ORIGIN='https://YOUR_APPROVED_BROKER_HOST'
ARSUMBRIS_SCRATCH=/home/user/.capy/work/arsumbris-runtime \
LX_RETRIEVAL_PROFILE=voyage node eval/compare-harnesses.mjs \
  --harvey-root /absolute/path/to/harvey-labs \
  --python /absolute/path/to/harvey-labs/.venv/bin/python \
  --native-module eval/comparison-preflight.mjs \
  --broker-origin "$BROKER_ORIGIN" --broker-port 8788 \
  --sandbox-template c2xsaop5g2ny362s3b8v \
  --computer-image-sha256 f60ce1097ee693a9bfd6281649cabbcf216572f935cfe1f9109c36a56e6dd29b \
  --limit 2 --concurrency 1 \
  --artifacts /absolute/scratch/path/comparison-2 \
  --output /absolute/scratch/path/harvey-broad-luna-2.json
```

Use distinct artifact and output paths at each stage. Advance to `--limit 4`, then `10`, then `15`, adding `--previous /absolute/path/to/the-immediately-preceding-output.json`. The runner rejects a changed configuration/protocol or a preceding gate with missing, failed or degraded cases; the same native module, upstream/profile/corpus hashes, template/image hash, broker policy, model and evidence policy must carry across a gate sequence. These are overlapping prefixes, not 31 independent questions. It rejects any limit outside 2/4/10/15. After an implementation, provider, ingress or policy change, start a new sequence at two questions with new artifact/output paths instead of treating old scores as the same comparison. Do not substitute a model when access fails.
