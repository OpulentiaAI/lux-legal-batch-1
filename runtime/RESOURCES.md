# Resource tool contracts

The startup JSON and later MCP schemas define the knowledge, secret, attachment, and management actions in `resources.mjs`. The catalog only names `install_personal_plugin`, `manage_personal_plugin`, and `suggest_skill_pr`; it does not capture their callable input schema. This runtime defines these local inputs explicitly rather than claiming exact compatibility with the historical source schemas:

- `install_personal_plugin({url})` downloads a public HTTPS JSON manifest with `name`, `version`, `kind` (`tool` or `skill`), and `download_url`. It downloads the referenced payload into the E2B sandbox. A tool payload is a Node ESM program stored as `entry.mjs`; a skill payload is Markdown stored as `SKILL.md`. Neither is run on the control-plane host.
- `manage_personal_plugin({action,id,input?})` supports `list`, `get`, `invoke`, and `remove`. `invoke` runs only a tool payload in E2B as `node entry.mjs <base64-json-input>`; the program writes one JSON value to stdout. A nonzero exit or invalid JSON fails the call. `skill({command:'invoke',skill:<installed plugin name>})` reads an installed skill payload.
- `suggest_skill_pr({name,content})` creates a pending approval. Approval also requires explicit `repo`, `base`, `branch`, and `title`; missing fields leave the request pending. The repository must be in `config.allowedRepos`, the sandbox `origin` must match the GitHub repository, and its existing Git identity must match configured `authorName`/`authorEmail`. `GITHUB_TOKEN` is passed only as an E2B command environment value for the branch push. Only after the push succeeds does `ctx.invoke('git_create_pr', {repo,title,head_branch,base_branch,body,draft:true})` create a draft PR. Nothing merges implicitly.

The human HTTP handler, after authentication, calls the separately exported `approveResource(ctx, {kind,id,approve,value?,repo?,base?,branch?,title?})`. Kinds are `knowledge`, `mcp`, `secret`, `secret_save`, and `skill`. The request must belong to `ctx.sessionId`. `value` is accepted only for an approved `secret` request and is never stored or returned. Durable org-scope approval sends it directly to the E2B write-only Secrets API. A session-only request instead requires `ctx.injectSessionSecret({sessionId,name,value})`, which must inject only into that session's sandbox and clear the value on session termination; without that provider the request stays pending. `secret_save` reads the requested sandbox file and deletes it after successful creation or rejection. E2B's project secrets do not enforce narrower user/repo scopes, so those approvals are rejected rather than widened. MCP approval requires an HTTPS URL in `config.allowedMcpUrls`, probes it through `ctx.probeMcp(candidate)` before storing the installation, and publishes it only after a successful handshake. This explicit allowlist is required because the current MCP client has no DNS-pinned transport.

Attachments return opaque `storage://<id>` references backed by code.storage commits. The reference resolves through durable `ctx.store` metadata to a configured artifact repository and exact commit SHA; it never contains a signed download token. Arbitrary public downloads require HTTPS, resolve to public addresses, pin the connection to a checked address, reject redirects, and enforce a 10 MB limit.
