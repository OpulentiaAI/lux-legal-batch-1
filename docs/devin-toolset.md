# Devin toolset as a reference for the Luxembourg legal harness

## Required target and current gap

The implementation requirement is **end-to-end coverage of the entire captured Devin toolset**, not an inventory or a corpus-only subset. The 59 startup tools and 20 later MCP management tools below form a 79-tool minimum; later runtime surfaces must also be reconciled, with aliases and replacements identified rather than silently omitted. Each implemented tool needs a real backend, coverage of its supported actions, and end-to-end evidence of the resulting behavior. Schema registration, mocked tests, generic forwarding without a connected provider, and `unsupported` responses do not satisfy this requirement.

The current pull request implements a bounded legal retrieval/composition harness, **not this full tool runtime**. The inventory below records documented/captured interfaces, not a claim that this repository implements Devin or can call its private APIs. The hosted integrations listed at the end are outstanding implementation and verification gaps, not exclusions from the requested deliverable. Closed-corpus restrictions apply to the legal benchmark's evidence policy, not to the full harness's capability scope.

## What exists in this legal repository

`lx_search` implements hybrid/vector/BM25 retrieval with optional rerank, filters, inferred statute pins and weak-hit expansion; `lx_chunk` hydrates a cited chunk; `lx_documents` enumerates the nine documents; `lx_namespaces` inspects the live turbopuffer index (`docs/mcp-tools.md`, `docs/retrieval.md`). The extraction/structure/index scripts produce manifest-backed chunks with document, article and structure provenance. These four registered MCP tool types and their `src/tp` implementations are **real repo code**, while hosted index/embedding/rerank services require their existing credentials; `lx_namespaces` is operational introspection, not evidence for an answer.

**Pre-refactor historical baseline (commit `1639c7f`):** `eval/gold.json` has 50 questions with atomic rubrics; `eval/run.mjs` measures evidence/doc hit, MRR and latency; the committed `eval/compose.mjs` composes bounded French answers from hydrated chunks, judges rubric criteria, and optionally uses a depth-one planner (`--rlm`, 1–3 queries, at most eight sources). It calls an AI gateway and retrieval services, so it is not a fully offline benchmark. Critically, that judge receives the answer and **source IDs only, not the source text** (`eval/compose.mjs:90-94` at the baseline commit); its `grounded` and `citation_ok` judgments cannot verify whether claims or citations are supported. The `docs/retrieval.md:125-131` figures (86.0% versus 87.1% rubric pass) are **historical, untrustworthy as grounding evidence and not comparable with repaired grading**. Re-run matched cases with a judge given source bodies and checked citation IDs before claiming quality gains; do not extrapolate a benefit from those figures or call the pipeline an implementation of Devin workflows.

## Legal-benchmark execution policy within the full harness

1. Expose a **read-only corpus capability**: inventory (`lx_documents`), bounded discovery (`lx_search`), hydrate (`lx_chunk`), and optionally index health (`lx_namespaces`, never as a source). Pin allowed document/chunk IDs and the corpus/index version for each run; enforce scope at the adapter, not only in a model prompt. Preserve doc ID, article/section locator, chunk ID and page where available. Resolve every final citation against actually supplied chunk IDs, distinguish primary statute from secondary treatises, and abstain on missing evidence. No web search fallback: the nine PDFs omit tax, funds, employment, case law and English translations.
2. Make the **execution trace explicit**: question → search/filter/query-mode events → ranked hits → hydrated evidence → answer/citation IDs → rubric outcomes. Apply result-size/time/cost bounds and record service/model versions, failures and seeds/config where applicable. This borrows Devin's discover→invoke→observe and structured workflow principles without impersonating its shell, browser, control plane or script bridge. Keep licensed PDF text out of public logs/artifacts and obtain publisher clearance before external redistribution/model ingestion.
3. Keep **evaluation independent of the agent**: retrieval diagnostics (`eval/run.mjs`); LAB-inspired atomic factual, attribution, citation and unsupported-claim criteria (`gold.json`); answer composer and rubric judge (`compose.mjs`); optional bounded RLM-style query decomposition against the *same* pinned corpus. The judge needs hydrated source text and verified citation IDs, rather than the historical ID-only prompt. Compare flat and decomposed runs on identical cases, report per-criterion failures and abstentions, and validate a sample of judge decisions with legal reviewers. LAB/RLM are design inspirations here, not a claim of reproducing Harvey's proprietary systems.

## Outstanding end-to-end implementation gaps

- Devin persistent PTY (`exec`/`get_output`), browser CDP, desktop/VNC, recordings, browser profile, preview, attachment URLs, deployments, snapshots, environment blueprint, voice calls and secrets. The captured VM had a host-shared `devin-remote` binary, PTY service, long-lived Chrome and VNC/noVNC (`05-runtime-and-machine`); none is a repo-provided backend. Do **not** implement fake terminal/browser/cloud responders.
- Devin sessions/subagents, dynamic workflow replay, scripted tool bridge, billing/oncall/automations, code scan/review, user messages, approvals and organization knowledge/MCP installation. These require actual Devin APIs, session identity, authorization, lifecycle and billing; a JSON schema alone cannot satisfy them.
- GitHub/Linear/Slack/OneDrive/Jira/third-party MCP and unrestricted web research remain disabled inside the closed-corpus benchmark's answering path. Developer-side git or configured index/AI-gateway access does not turn those services into legal evidence. To complete the full tool runtime, these integrations need specified providers, permissions, data/license boundaries, auditable failure behavior, and tested real backends outside that benchmark restriction.
