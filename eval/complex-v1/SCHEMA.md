# Complex v1 task and judgment contract

This is a validation/staging library, not a model runner. `validateBundle({root,task,rubric,sources})` validates a normalized bundle; `prepareJudgeRequest(bundle,outputDir,criterionId,visibleSources)` prepares one criterion; `validateJudgeResponse(raw,request)` validates a strict response; `reconcileJudges(request,first,second)` retains both judges and returns `pass`, `fail`, `unresolved`, or `executionFailure`. The caller must capture answerer-visible tool evidence, pin the run policy and hashes, and keep private rubric/reference files out of the answerer workspace and corpus index. `outputDir` is the directory containing completed deliverables; `root/materials` holds public scenario files.

**Public `task.json`** has exactly `id`, `title`, `instructions` (nonempty strings), `scope` (exactly `{jurisdiction,companyForm,asOf}` with nonempty strings), `deliverables` (nonempty array of distinct basenames), and `materials` (array of `materials/<basename>` strings). Materials and deliverables use single-level `.md`, `.csv`, or `.txt` files, ASCII alphanumeric first, then ASCII alphanumeric, `_`, `-`, or `.`; no arbitrary paths, symlinks, filename case collisions, or other formats. Validating a bundle computes SHA-256 of material bytes in `materialHashes` for run freeze; hashes are **not** added to public task.json. Draft tasks with a different shape must be normalized separately; this library does not guess aliases or silently change them.

**Private `rubric.json`** has exactly `criteria`, a nonempty array. Each criterion has exactly `id`, `requirement`, `pass`, `fail`, `deliverables`, `sourceRefs`, `factRefs`, `minimalPass`, `nearMiss`, `failureFamily`. Strings are nonempty. Criterion deliverables are a nonempty subset of the public map. `sourceRefs` entries have exactly `{id,sha256,quote}` and must point to an exact quote within a canonical `reference` source with matching hash. `factRefs` entries have exactly `{file,quote}` and must quote one verified public material file. Arrays may be empty. Each criterion should express one falsifiable obligation; `minimalPass` and `nearMiss` are calibration examples, not answer-string templates. `failureFamily` associates repeated manifestations of one root defect for diagnostics; it never automatically waives a distinct obligation. Source refs can establish truth but cannot establish model visibility; fact refs establish scenario facts, not law.

**Canonical sources** are an array of exactly `{id,sha256,text,role}`, with role `reference` or `visible`; reference IDs are unique ignoring case, hashes cover exact UTF-8 text. `validateBundle` resolves source refs from the workspace's canonical `corpus/index/chunks.jsonl` and `corpus/chunks/` by default, matching the declared hash and quote; `sources` is an optional injection for synthetic tests. Do **not** write full source text into a task packet. `visibleSources` is a separate argument containing only `visible` records verified against the answerer's captured tool output by the caller. Multiple independently printed excerpts may share one chunk ID; the exact quote/offset must match one record, never a stitched union. Do not infer visibility from corpus availability. The prepared request contains the selected criterion, only its named deliverables, its cited reference sources, its fact material files, and the explicitly supplied visible records. Missing named output is represented as `content:null`; corrupt/unreadable output throws rather than being interpreted as omitted content. Only exact text extraction of md/csv/txt is supported; DOCX/PDF is deliberately unsupported pending a separately tested extractor.

**Judge response** has exactly `{criterionId,verdict,reason,answerSpans,anchors,defectId,defectType,legalTruth,sourceCompliance}`. Verdict is `pass | fail | unresolved`; legal truth is `correct | incomplete | incorrect | unverified | not_applicable | unresolved`; source compliance is `met | unmet | not_required | unresolved`. Every `answerSpans` entry has exactly `{file,start,end,quote}` referring to the selected deliverable text. Every anchor has exactly `{role,id,start,end,quote}`; role is `source_reference | visible_source | scenario_fact`. Offsets are zero-based JavaScript string offsets and `end` exclusive; quote must equal that one record's exact substring. A fail has a nonempty `defectId`, `defectType` (`omission | false_rule | false_scenario_fact | unsupported_assertion | source_requirement | deliverable_requirement | other`), and quoted answer and source evidence except an omission/missing deliverable, which may have neither. Pass and unresolved have null defect fields. Pass requires a present scoped deliverable, answer span, non-failing truth/source status. Unresolved requires an unresolved truth or source status. The validator can verify shape and exact quote provenance, not the legal merits of reasoning; independent review still matters.

`sourceCompliance:"met"` requires an actual `visible_source` anchor, not a hidden reference or scenario fact. A `false_rule` fail needs at least one legal source (`source_reference` or `visible_source`), while `false_scenario_fact` needs a `scenario_fact` anchor. Source requirements and unsupported assertions need visible evidence; hidden references cannot prove consultation. `defectId` remains a concrete defect identifier rather than being forced to equal the author-side `failureFamily`; reconciliation reports can group it by that family without collapsing different failure mechanisms. Each scoped output is bounded at 1 MiB and decoded as strict UTF-8; invalid bytes, oversized files and a missing output directory are extraction errors, while a missing individual deliverable is represented by `content:null`.

Both raw judgments are preserved. A disagreement or either `unresolved` becomes unresolved; matching verdicts resolve. An invalid or unavailable judge response is `executionFailure` at judge stage; the caller should record retries and never fabricate a legal grade. Agent execution and file extraction failures are separate caller-side execution failures. All-pass task aggregation, dual raw statistics, adjudication and provenance-bound resume are future runner responsibilities, not implicit behavior here.

A pass claiming `legalTruth:"correct"` must quote at least one legal-source anchor, either a hidden reference for truth or an actually visible source. A scenario fact alone cannot establish legal correctness. The prepared response contract describes the evidence rules as well as the JSON fields; field validation is still not a substitute for semantic calibration.

`node eval/complex-v1/validate.mjs --root PATH [--workspace CORPUS_REPO] [--stage NEW_PATH]` recursively finds normalized packet directories containing `task.json`, `rubric.json`, and declared `materials/`. `--workspace` selects the repository with the canonical corpus and defaults to this repository. It validates every packet before staging. Optional `--stage` must name a new destination outside the repository and packet roots; staging copies **only** `task.json` and declared `materials/` files into packet-relative directories, never `rubric.json`, calibration, or other adjacent files. CLI JSON lists packet IDs and verified material hashes; a schema error exits nonzero. Stage paths and materials are checked for symlinks. This public stage is an output directory, not automatically an agent workspace or corpus index.
